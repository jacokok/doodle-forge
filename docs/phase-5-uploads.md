# Phase 5 — private original uploads

In `/characters`, save a character in **1. Character details**, move to **2. Private original**, then select **Original image** and **Attach original**. Step navigation retains the selected file and unsaved text/choices without submitting them; a successful upload clears only the selected file and updates the authoring revision. **3. Review and history** is read-only; it does not generate art. The editor displays a private preview and a link to the unchanged original. **Replace original** deliberately selects a new upload, retaining previous originals/previews immutably. It does not save unsaved metadata, generate artwork, create versions/jobs or change published content. Upload errors retain text and file selection. A stale revision or uncertain network result blocks further mutations until deliberate library reload; reload discards local edits/file selection. See [metadata authoring](phase-5-authoring.md).

## Safety and persistence

- Still JPEG, PNG or WebP only: 10 MiB encoded, 20,000,000 decoded pixels. Claimed MIME must match magic bytes; extensions and supplied filenames are not trusted or used as paths. Sharp fully decodes with strict warning handling and pixel bounds before adoption. Animated/multipage images (including APNG), malformed/truncated containers and undecodable pixels are rejected. PNG compressed ancillary metadata (`iCCP`, `zTXt`, compressed `iTXt`) is conservatively refused because decoded pixel bounds do not bound metadata decompression; export a plain PNG or JPEG/WebP instead.
- Original bytes are unchanged, SHA-256 hashed, and written exclusively to UUID-generated private keys. A separate PNG preview is EXIF-oriented, fits within 1024×1024 without enlargement, and has no inherited EXIF/ICC/XMP/IPTC metadata. Originals may still contain private metadata; only the preview is stripped.
- Additive migration 0003 adds asset metadata, source links, selected original references and immutable asset guards. Attachment/replacement increments the same optimistic character revision used by metadata edits/archive. Short immediate transactions adopt both asset records plus selection together only if the identity is still unarchived and at the expected revision. Concurrent metadata edits, uploads and archive cannot silently overwrite each other.
- Files are exclusively created, flushed and made read-only before DB adoption. Failed adoption/interrupted requests may leave unreferenced private files. No delivery route can resolve those files; no automatic deletion/retention or orphan cleanup is implemented. Keep coordinated DB/storage backups. This is not a tested power-loss durability guarantee.

## HTTP boundary

`POST /api/characters/:id/originals` requires exact same-origin `Origin`, multipart fields **image** (one file) and **expectedRevision** (positive safe integer string), and no other fields. Success is HTTP 201 with the updated character identity (including `originalAssetId`), not a job/version. Errors use the existing sanitized structured error protocol: 400 invalid fields/framing/revision, 403 origin, 404 missing/archived identity, 409 stale revision, 413 encoded/request size, 415 unsupported media type, 422 unsafe/invalid image, 503 operational failure.

The transport counts actual streamed bytes, cancels when exceeding **10 MiB + 64 KiB** multipart envelope, then parses only the bounded body. It does not call `request.formData()` on an unbounded stream or trust Content-Length. The file itself must be at most 10 MiB before its bytes are passed to Sharp. This is bounded in-memory parsing, not streaming to disk or an aggregate memory/concurrency quota. Set adapter-node **`BODY_SIZE_LIMIT=10551296`** in its process environment; any reverse proxy must enforce an equivalent request envelope. The adapter's default 512K remains safe but rejects larger otherwise-valid uploads. Keep JSON metadata mutations at their independent 16 KiB route limit. Adapter/proxy rejections can precede structured application errors.

`GET /api/characters/:id/originals/:assetId/{original|preview}` resolves a retained original ID belonging to that non-archived character. Both current and historical attachments remain privately readable by ID; archive hides all authoring image access without deleting bytes or revoking published content. Preview resolution follows its immutable source link. No filesystem paths/storage keys are accepted or returned. Reads reject symlinks/nonregular files, unexpected generated keys, size/hash corruption and unsafe private roots; operational corruption returns sanitized 503 without fallback. Responses are `private, no-store`, `nosniff`, same-origin resource policy and sandboxed image delivery. Storage is never statically mounted or published.

These are **local loopback private routes**, not authenticated multi-user authorization. Do not expose studio on a LAN/public host; ownership/authentication, retention/consent review, aggregate quotas and HTTPS are separate prerequisites. A private original is never a public game-content asset.

## Verification boundaries

`originals.test.ts` uses real Sharp, migrated temporary SQLite/storage and separate connections for safety, immutable hashes/bytes, preview orientation/metadata/dimensions, confinement/corruption and attachment races. `tools/browser-tests/originals.spec.ts` uses the real built studio for keyboard upload, preview/error/replacement, retained unsaved metadata/file selection, stale attachment and pending/uncertain network behavior. Exact executed results are in [progress](../plans/14-progress.md). No upload-to-generation E2E, full accessibility/child-usability audit or full Phase 5 acceptance is claimed.
