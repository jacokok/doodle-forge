# Phase 5 — metadata authoring increment

Phase 5 includes a guided metadata library/editor, [safe private original upload/preview](phase-5-uploads.md), frozen review/history, explicit fixture review/publication actions and the JSON API below, not full Phase 5 acceptance. The review step now compares the current private original beside a frozen animation when its supported fixture or ready-package source is available. Original art is explicitly labeled as current mutable authoring art, not necessarily the source of the selected frozen version. Animation/frame metadata comes from the shared manifest contract; playback follows its FPS/loop fields, offers keyboard-operable frame controls, honors reduced-motion preference and is stopped when the review step/version becomes inactive. Failed images are not substituted. Supported unpublished fixture sheets have a separate private review route. Review/publication controls are implemented; comprehensive accessibility/observed child-usability acceptance remains pending. Generation remains unavailable.

## Metadata library

Open **Character library** from the studio home page, or visit `/characters`. The responsive editor has three steps:

1. **Character details**: enter the five authoring fields and explicitly **Save metadata**. New identities must be saved before the other steps unlock.
2. **Private original**: optionally attach/replace immutable art. Upload does not submit unsaved details.
3. **Review and history**: inspect a summary of current local input (explicitly not a frozen version), real frozen versions, append-only review decisions and ready-release membership; explicitly confirm review/publication actions. Generation/jobs are explicitly unavailable.

Use the numbered step buttons or Previous/Next step; transitions focus the step heading and never save or discard input. Inactive panels remain mounted so selected files and local text/choices survive navigation. Inputs have native keyboard controls; layouts stack on narrow screens. This is automated keyboard/responsive evidence, not an accessibility or child-usability acceptance claim.

Create an identity with name, description, body type, fighting style and special power; select an existing identity to edit it. Fighting style offers **Not selected** (`unselected`) and **Light melee** (`light_melee`). Special power offers **None** (`none`) only: no special powers are implemented. These selections are authoring intent; they do not change runtime gameplay. The existing runtime implements light melee, not a mapping from these editor choices to generated combat data (ADR-029). These are mutable authoring fields, not a generated version or publication status. Names/descriptions render as plain text. The editor explicitly reports generation/jobs unavailable until Phase 6; no job is queued and no retry/cancel controls are implied. Unsupported features are labeled unavailable; no successful generation, version or job is fabricated.

The same-app UI uses thin SvelteKit remote queries/commands over `CharacterService`, not fetch wrappers or legacy load/actions. The editor includes a frozen-version browser: select a version to inspect its frozen manifest identity/metadata, latest hash-bound approval and append-only decision history, and ready-release membership. For a ready-release member, the comparison shows the current private original (if present) beside the selected version's manifest-driven animation; original image bytes remain owner-checked and private; released sheets use the validated public content route. Browsing leaves unsaved editor inputs untouched. Approval is reported separately from publication; only membership in a `ready` release establishes published visibility. Supported unpublished fixture snapshots can also be reviewed through a confined private sheet route. Other unpublished packages remain unavailable until Phase 6 provides registered sources. Animation selection and frame controls use actual manifest values; automatic playback honors reduced motion and does not run outside the active review/version. Loading and failed-image states do not substitute another version or asset. Corrupt/missing snapshots and empty histories are explicit. The existing private original preview remains clearly mutable authoring art, not frozen artwork. Shared contracts validate domain inputs and supply body-type and creative-choice options. Unknown legacy creative strings are labeled **Unsupported stored choice** and retained on metadata-only saves; deliberately replacing them accepts only the supported choices. They are never presented as executable abilities or silently converted. Expected revisions remain attached to the loaded editor snapshot. Validation errors retain input and identify fields; stale edit/archive conflicts block mutations and retain local text. Copy anything needed before deliberately using **Reload library and discard local edits**; there is no automatic retry with a newer token. Selecting another library entry or New character while input or a selected file is unsaved requires explicit discard confirmation; Cancel keeps the current step and all input. Leaving the page also warns about unsaved input (native browser warning on reload/close where supported). This is in-memory retention, not durable autosave: confirmed discard/leave loses local work. Explicit reload of an existing identity still replaces local input with the authoritative snapshot.

Mutations disable editor/library controls while pending. Network failures keep input and block resubmission until a deliberate reload because a lost response does not prove the server did not save. For an uncertain create, check the reloaded library for the saved identity before creating another. Query failures retain input and offer reload. Archive has a separate confirmation with keyboard focus initially on Cancel; it discards unsaved metadata but never revokes published content.

Remote outcomes carry sanitized structured errors and reference IDs, while framework transport errors use an explicit uncertainty message. Remote functions retain SvelteKit's origin protection plus an explicit same-origin domain-dispatch guard; adapter request limits apply. The JSON-specific 16 KiB/UTF-8 transport policy below remains specific to the preserved JSON API. See setup for the pinned framework's build-time origin requirement.

## JSON API

- `GET /api/characters`: `{characters:[...]}` for non-archived identities.
- `POST /api/characters`: required `{name,description,bodyType}`, optional `fightingStyle`/`specialPower` (defaults `unselected`/`none`); returns the new identity with HTTP 201 and `editRevision:1`.
- `GET /api/characters/:id`: current non-archived identity.
- `PATCH /api/characters/:id`: `{expectedRevision,...authoringChanges}`; at least one metadata or creative-choice field required. Omitted fields are unchanged; choice-only and mixed edits are atomic. Returns the identity with incremented revision.
- `DELETE /api/characters/:id`: JSON `{expectedRevision}`; archives the identity, increments its revision, returns empty 204. This is not physical deletion or unpublication.

Metadata uses the shared browser-safe `@doodleforge/contracts/authoring` schemas. Name is trimmed, 1–80 Unicode code points; description is trimmed, at most 2000; body type is `humanoid`, `quadruped`, `floating` or `other`. Text is plain text, not HTML; views render escaped text. Unknown fields are rejected. Choices accept only exact canonical strings: fighting style `unselected` or `light_melee`, special power `none`. Unsupported/unknown values, arbitrary ability/configuration fields and wrong types are rejected, including on legacy rows when explicitly submitted. Metadata-only clients remain compatible; defaults apply only on create, not PATCH.

Mutations require `Content-Type: application/json` and an `Origin` exactly matching the request URL origin, including for non-browser clients. Bodies are limited to 16 KiB while reading, without trusting Content-Length; invalid JSON/UTF-8 is rejected. The adapter's existing request-size cap still applies independently. This loopback-only API is not authenticated multi-user hosting. The same-app UI uses thin remote functions over the domain service (ADR-026); these explicit routes remain the planned JSON API, not client fetch-wrapper guidance.

Responses are `no-store` with `nosniff` and an `X-Request-Id`. Failures have `{error:{code,message,fieldErrors?,requestId}}`: 400 invalid input/JSON, 403 missing/wrong origin, 404 missing/archived identity, 409 stale revision, 413 size, 415 media type and sanitized 503 operational failures. Reload and reconcile edits after 409; do not blindly retry with a newer token. Metadata, creative-choice edits and archive use a conditional database update against the expected revision and non-archived state; upload attachment uses the same revision. Never retry with a newer revision automatically. Upload keeps unsaved local creative selections without submitting them.

## Content boundary

Authoring identities are mutable; frozen review snapshots, approvals and ready releases are not changed by editing or archiving. Archive hides an identity from authoring list/get and prevents further edits; historical published membership remains available through the content API. Metadata/upload operations create no frozen version, approval, job or release; explicit frozen-version actions below are separate. Changing published content still requires a separate new frozen version, approval and publication. No new migration was needed for metadata or creative choices; existing identity columns hold the choices, not version ability rows. Upload migration 0003 adds immutable original/preview assets and a selected original reference; attachment shares the identity's optimistic edit revision. See the [upload policy and private HTTP boundary](phase-5-uploads.md).

## Review and publication actions

Select an existing frozen version in Review and history. Inspect its metadata and animations, then use **Approve version**, **Reject version**, **Revoke approval** or **Publish version**. Every action requires a Cancel-first modal confirmation naming the exact version ID/hash. Approval does not publish; publication requires the latest matching approval. Rejection/revocation does not remove historical ready releases. Unsaved authoring fields are never submitted by these actions. There is no generation or publication job implied by a command.

The Phase 5 bounded fixture command returns an actual result synchronously; Phase 6 will move generated-package publication to durable jobs (ADR-031). Sources are only allowlisted Sprout/Comet v1 fixtures or already-ready immutable packages, with matching canonical manifest hash. Per-package admission: at most five sheets, 2 MB compressed and 2 million declared pixels; catalog admission: eight identities. Clients cannot supply paths, actor identity or replacement manifests. Larger/generated unpublished packages report unavailable rather than enqueueing fictitious work. New ordinary uploads still have no frozen version.

**Refresh review** deliberately reloads decision state without discarding authoring input. A competing decision, archive, hash mismatch or uncertain response blocks further actions until refresh. A lost response may mean the action completed; inspect latest decisions/release membership. Publication is idempotent while the exact revision remains active, not a request to resurrect an old release. To recover interrupted publication, use the operator reconciliation guide after stopping publishers.

- `POST /api/characters/:id/versions/:versionId/approvals`: JSON `{expectedManifestSha256,expectedDecisionOrder,decision}` where decision is `approved`, `rejected` or `revoked`.
- `POST /api/characters/:id/versions/:versionId/publish`: JSON `{expectedManifestSha256,expectedDecisionOrder}`; actual 200 `{releaseId}` on success, not 202.
- `GET /api/characters/:id/versions/:versionId/assets/:assetId`: private/no-store PNG sheet for a supported owned frozen source; unknown/archived/wrong-owner sources fail. No public visibility is granted by this route.

JSON mutation routes reuse exact-origin/16 KiB/structured-error protection. Same-app remote commands use framework origin protection plus the same explicit origin guard/domain service. The server uses `local-studio-reviewer` as an audit label, not an authenticated account. This remains loopback-only, not hosted multi-user access.

## Animation playback

Supported frozen previews have Pause/Play, Previous/Next frame and Restart controls. Frame stepping pauses playback; Restart starts at frame one (but never overrides reduced motion). One-shots stop at the last frame; Play or Restart can replay them. Explicit pause is retained when choosing another animation/version of the same identity; opening another identity resets it. Playback stops while the review step or browser tab is hidden, during loading or on asset failure. No new art delivery authority is added: unsupported unpublished sources remain unavailable.

## Accessibility follow-up

Mutation failures focus the error summary unless a metadata field can be focused directly. Archive/removal recovery restores focus to New character; upload requirements describe the file input. Unsaved-input text is intentionally not a live announcement on every keystroke. See [focused coverage and outstanding manual checks](phase-5-accessibility.md); comprehensive accessibility and observed child-usability acceptance remain pending.

The harness builds for its isolated origin and cleans temporary data on shutdown. Progress records exact executed checks. Automated Chromium coverage also exercises frozen-version keyboard selection, pending/history failures, empty and archived identities, approved-but-unpublished versus ready-published fixtures, released preview delivery and unsaved-input retention while browsing. This is focused browser/keyboard coverage, not a full accessibility audit, child-usability observation, upload-to-generation/factory E2E or manual graphical acceptance.
